# CLAUDE.md: rules for working on Linkle Companion

Read this file and `docs/PROGRESS.md` first in every session, then continue from "Next step" in PROGRESS.md.

## What this is
A standalone Fabric mod (`linkle_companion`) that adds Linkle, a dual-crossbow follower companion.
Open source: code MIT, original assets CC BY 4.0. Unofficial fan project, no monetization.

## Pinned versions (see docs/DECISIONS.md)
Minecraft 26.3, Fabric Loader 0.19.5, Loom 1.18-SNAPSHOT, Fabric API 0.161.0+26.3, Java 25, Gradle 9.7.1.
Minecraft 26.x is unobfuscated: code uses Mojang's official names directly (no Yarn, no mappings line).

## Hard rules
- Work autonomously. Unclear? Pick the most reasonable option, log it in `docs/DECISIONS.md` with a one-line reason.
- Keep `docs/PROGRESS.md` honest and current. Commit after every finished feature, small clear messages.
- After each feature: play-test if possible, list its 3 biggest problems, fix them, then move on.
- Never claim something works unless it was run; show output. Untestable items go in `docs/TESTING.md`.
- Standalone: no dependency on other mods except Fabric API. No shared library. Everything under the
  `linkle_companion` namespace (ids, lang keys, config file, network channels, data, keybinds).
- Compatibility: never `@Overwrite`, never replace vanilla loot tables/recipes/tags/registries (only add).
  Prefer Fabric API events; any mixin must be small `@Inject` with a narrow target, documented in
  `docs/ARCHITECTURE.md`. Use `c:` convention tags and vanilla tags over hardcoded items.
  Fail safe: log one warning and disable a feature instead of crashing.
- Client-only code lives in `src/client`. The dedicated server must start (`runServer`).
- Performance: vanilla goals, throttled expensive checks, no per-tick allocations, nothing runs when idle.
  Vanilla sounds and particles only.
- Legal: everything original. Never open, extract or use Nintendo/Koei Tecmo game files, ripped models,
  textures, audio, logos or quotes. Never bundle a skin without redistribution permission. The skin is
  generated by `scripts/art/generate_skins.py`.
- `references/` and `tools/` are git-ignored. Never commit reference images.
- Machine: log every install in `docs/DECISIONS.md`. Don't touch unrelated software/files. Never push or publish.
- Launcher: Freesm Launcher portable at
  `C:\Users\Admin\Downloads\Games\FreesmLauncher-Windows-MinGW-w64-Portable-2.3.1`. Only touch instances
  named `dev-linkle_companion*`. Never read/copy/log `accounts.json` or tokens. The author allowed launching
  with their own default account: `freesmlauncher.exe -l dev-linkle_companion`. Do NOT use `-o <name>`.
  Unattended play-tests: `./gradlew runJoinTestServer` or `cleanInstallClient` (offline name DevTester).
- Test clients must start muted and be closed when the check is done (the author dislikes background game noise).
- Test servers: `testserver/` (git-ignored); eula=true and online-mode=false only there.

## Useful commands
- `./gradlew build` builds the jar into `build/libs/` and runs the server game tests.
- `./gradlew runDatagen` regenerates `src/main/generated` (recipes, lang, tags, advancements).
- `./gradlew runServer` / `./gradlew runClient` are dev runs.
- `python scripts/art/generate_skins.py` regenerates the skins.
